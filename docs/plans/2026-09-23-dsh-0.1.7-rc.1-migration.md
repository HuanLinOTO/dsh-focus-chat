## 改动

### 1. RC1-01 cohort
- peerDependencies：`>=0.1.5-rc.1` → `^0.1.7-rc.1`（14 项）；`@deepseek-ai/cordis` 保持 `>=4.0.1`。
- 新增 peer `@deepseek-ai/dsh-api-session-controller@^0.1.7-rc.1`（现在直接 import `PendingSubmission`/`SessionSnapshot` 类型）与 `@deepseek-ai/dsh-client-ui-workspace@^0.1.7-rc.1`（`ctx.uiWorkspace` 的 Context 增补）。
- `dsh.client.inject` / `dshClient.inject` 增补 `@deepseek-ai/dsh-client-ui-workspace`（运行期模块边）。

### 2. RC1-23 toolview 三阶段
`src/client/model/tools.ts`：
- `parsedCall`：`'kind' in block ? block.call : block.phase === 'preparing' ? null : block`（preparing 无参数，返回 null）。
- `toolRowModelUncached`：`argsRaw = done ? block.call?.argsRaw ?? '' : block.phase === 'preparing' ? '' : block.argsRaw`。

### 3. RC1-24 chat-node 重塑
`flow.ts`：
- `CHAT_KIND_DISPOSITION` 增 `'turn-trigger': 'message'`（满足 `Record<ChatNodeKind,string>` 穷尽校验）。
- `flowItemOf` 的 message 分支纳入 `'turn-trigger'`（其 data 是 `ContextMessageNode`），role 归一到 `'context'` 渲染；`context.provenance` → `context.producer`。
- `turn-tail`：`ttftMs` 由 `closing.finalNode.timing`（`firstTokenTime - stepStartTime`）派生；`tokensPerSecond` 由 `tokenUsage.outputTokens / decodeMs` 派生；deliverables 通过局部窄化读取（见「跳过/pending」）。
`types.ts`：`ContextMessageNode['provenance']` → `['producer']`。
`ContextRow.tsx`：`context?.provenance` → `context?.producer`。

### 4. RC1-26 图标改名
`*Outline16/Fill16`→`*OutlineRegular/FillRegular`；`*Outline14/Fill14`→`*OutlineMedium/FillMedium`；`IconSparkle16`→`IconSparkleRegular`；`IconFolderClose16`→`IconFolderCloseRegular`。共 14 文件 21 符号。

### 5. RC1-14 工具名表
`tools.ts` / `icons.tsx`：移除 `cordis_run`/`cordis_stop`/`cordis_undefine`/`cordis_runtime_inspect`/`cordis_package_inspect`，改为 `cordis_inspect_list`/`cordis_inspect_query`（read 变体 + `tool.title.inspect`）。

### 6. 其它契约漂移（随 tsc 暴露，一并修）
- `ui-primitives` 卡片标签：`TerminalBlockLabels` 新增必填 `noExitCode`；`DiffBlockLabels`/`ReadBlockLabels` 继承 `CodeToolbarLabels`（新增 `codeLabel`/`wrapLabel`/`unwrapLabel`），`DiffBlockLabels` 去掉 `files`。新增 4 个 `focus` 词典键（zh/en 各一）。
- `ISessions.open` 移除：`apply.ts` 的 fork 后导航改为 `ctx.uiWorkspace.openSession(childId)`；`inject` 增 `'uiWorkspace'`，并 `import type {} from '@deepseek-ai/dsh-client-ui-workspace/client'`。
- `SessionSnapshot.queue` 移除：`FocusView.tsx` 改读 `s.pendingSubmissions`（本地提交回显），`PendingSteeringBubble` 改吃 `PendingSubmission`（`text` + 图片 `previewUrl` + file 附件）。
- 测试夹具同步：`runningCall` 加 `phase:'start'`；`nodeStoreOf` 加 `turnDataSource`；`SessionListState` 改 `{ids,byId,phase,projectionsBySession}`；`queue`→`pendingSubmissions`；`tool-result` ContentBlock 换成 `tool-addition`（保留 21k 超长 JSON 断言）。

## pending / 残余风险

- **测试无法在 0.1.7 下运行（环境限制）**：本插件 `vitest.config.ts` 用 alias 把 `@deepseek-ai/dsh-client-*-/client` 直接指到本地只读 checkout `../dsh/packages/.../src`（0.1.5-rc.2）；`dsh/` 只读，无法构建 0.1.7。若强制用 registry 0.1.7，`@deepseek-ai/dsh-client-test-runtime@0.1.7-rc.1` 的发布产物 import 了 `@deepseek-ai/dsh-api-session-controller/src/client/scope.ts`（该包 `files` 不含 `src/`），且 `@deepseek-ai/dsh-client-store@0.1.7-rc.1` 运行期 import `immer` 而发布包未声明该依赖——两者都是上游打包缺口。因此测试只在基线的本地 checkout 配置下有意义；迁移的静态层证据为 typecheck + build。**需在本地 dsh 升到 0.1.7-rc.1 后复跑 `pnpm test`。**
- `ContextMessageNode.producer` 的 `deliverables` turn data：`@deepseek-ai/dsh-client-ui-deliverables@0.1.7-rc.1` 把 `ConversationTurnDataMap.deliverables` 增补放在 `turn-deliverables.d.ts`，而该文件未从 `client/index.d.ts` 可达（发布包无 `src/`），外部消费者拿不到合并。`flow.ts` 用局部 `as unknown as { get(key): FocusDeliverablesData | undefined }` 窄化读取，形状与上游一致；上游补齐后再回退为直接 `turn.data.get('deliverables')`。
- `ttftMs`/`tokensPerSecond` 改由 `AssistantTiming`/`TurnTokenUsage` 派生：数值口径可能与上游旧 builder 略有差异，建议真机核对。
- `turn-trigger` 节点在本视图渲染为 context 行（其 data 为 `ContextMessageNode`）；上游专门的 `turnTriggerDetails` 图标/文案未接入，属可选增强。
- `PendingSteeringBubble` 现在只覆盖本浏览器的本地提交回显（旧的权威 queue 已移出 `SessionSnapshot`）；其他客户端的入队不再显示。
