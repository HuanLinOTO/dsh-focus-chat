# @huanlin/dsh-focus-chat · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 生成日期：2026-08-30 · 分析基线：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)，234 commits。
> 本指南只读分析了 `D:/Projects/deepseek-harness/dsh`（运行中 dsh 的只读源码树，git show/diff/grep）与插件自身源码；未修改任何文件。

## 结论

**✅ 直接可升 —— 源码零改动。** 插件消费的每一个 dsh 面（`connection.generation`、`conversation.view` 槽位契约、ui-chat 快照类型、ui-session kit、`ctx.remote.session/messageFeedback`、ui-primitives 组件）在 alpha2 中要么逐字节未变、要么仅做向后兼容的增量；唯一被上游改名的注入 hook `connectionGeneration → hostInfo`（ui-tool/ui-workspace）本插件从未使用。升级动作只是：更新 dsh source → 重建 `lib/` → 重启验证。风险集中在**本地 junction 依赖解析**（见「迁移步骤」第 2 步），不在 API 兼容性。

## 迁移步骤

**源码零改动** —— 不需要修改 `src/`、`cordis.patch.yml`、`package.json` 的任何内容。按顺序执行：

1. **升级 dsh 源码（人类执行，遵循 AGENTS.md「更新 DSH 源码 checkout」SOP）**：
   ```powershell
   $src = "C:/Users/Administrator/.dsh/source/current"
   git -C $src pull --ff-only origin master     # 或检出到 dsh-v0.1.2-alpha.2
   pnpm install --prefer-offline               # workdir=$src；新 workspace 包需 link
   pnpm run build                               # 全量构建，前台长 timeout
   ```
2. **确认插件 junction 完好（关键步骤，勿跳过）**：junction 指向 `$src` 的子目录，源码升级后它们**自动**变成 alpha2 内容，无需重建；但**千万不要在插件目录重跑 `yarn install`**——lockfile 里记着 npm 的 rc.2 版本，yarn 会用 npm 副本**覆盖 junction**，类型与测试会静默退回 rc.2 面。校验：
   ```powershell
   Get-ChildItem D:\Projects\deepseek-harness\dsh-focus-chat\node_modules\@deepseek-ai |
     Where-Object LinkType -eq 'Junction' | Measure-Object   # 应仍为 22 个
   ```
   若被覆盖：按 README「Development」节重建 junction（删除对应 node_modules 子目录后 `New-Item -ItemType Junction -Target "$src\packages\<group>\<pkg>"`）。
3. **重建插件类型面与 lib/（Windows 下勿用 `pnpm run clean`，脚本里的 `rm -rf` 在 win32 不存在）**：
   ```powershell
   Push-Location D:\Projects\deepseek-harness\dsh-focus-chat
   Remove-Item lib -Recurse -Force -ErrorAction SilentlyContinue
   yarn run typecheck      # 经 junction 现在编译的是 alpha2 的 TS 源（vitest.config.ts 的 alias 指向 junction 的 src/）
   yarn test               # 同上，测试图运行在 alpha2 源上
   yarn run build          # tsc + tsdown → lib/index.js / lib/invariant.js / lib/client.js
   Pop-Location
   ```
   验证产物：`Test-Path lib\client.js`，且文件以 `window.__ModuleLoader__.load({ id: '@huanlin/dsh-focus-chat'` 开头（DSSH 模块加载器契约）。
4. **profile 端可见性（`link:` 引用，无需重装）**：`lib/` 重建后，`C:\Users\Administrator\.dsh\profiles\web\node_modules\@huanlin\dsh-focus-chat\lib\` 直接看到新产物；`dsh plugin --profile web update` 对 link: 依赖是无效操作，不要执行。
5. **重启与刷新（人类执行）**：重启 `dsh web` 进程 → 浏览器 `Ctrl+Shift+R` 硬刷新。
6. **（可选，建议后续提交）声明卫生**：devDependencies 中 `@deepseek-ai/*` 从 `0.1.1-rc.2` 系对齐到 `^0.1.2-alpha.2`（注意 alpha 走 npm 独立 dist-tag）；按 SOP F2 把运行时 externals（`@deepseek-ai/cordis`、`dsh-client-store`、`dsh-client-ui-slots`、`dsh-client-ui-primitives`）与注入 roster 声明为 peerDependencies；README「Development」节 "targets the dsh v0.1.2-alpha.1 client surface" 措辞同步更新。这些都可留到下一个常规版本，不阻塞本次升级。
7. **对外发布**（如有）：走 huanlinoto 发布 SOP —— 重建 lib/ → 提交推送 → `dsh plugin --profile web update @huanlin/dsh-focus-chat`（github: 引用场景）或 `pnpm publish`（npm 场景）。本机 profile 是 link: 引用，第 3 步完成即已生效。

## 升级后验证清单

> 全部在「dsh web 已重启 + 浏览器 Ctrl+Shift+R」之后进行。

1. **标签页挂载**：打开任意对话，出现「聚焦对话」标签（`cordis.patch.yml` 的 `ui-focus` insert 行随启动生效）；点切无白屏、无 console 报错（F12 查看 `[dsh-focus-chat]` 相关）。
2. **折叠摘要行**（核心功能，覆盖 ui-chat 契约零差异的结论）：发一条会调用工具的消息 → 助手回合收成「思考了 N 秒，运行了 N 个命令…」摘要行；展开可见工具卡片（Diff/Read/Search/Terminal/Web 卡）与思考行；运行中的行先以活动行出现、结算后折入。
3. **`~` 路径缩写**（覆盖 `connection.generation` host facts）：工具摘要中的绝对路径显示为 `~/…`；若显示完整 POSIX home 路径，说明 host facts 链路有变，回查 `connection.generation`。
4. **产物 chips 与打开文件**（覆盖 `isLoopback` + `remote.session.openWorkspacePath`）：编辑/读取类工具行出现产物 chip，点「在文件夹中显示」能唤起系统文件管理器；拒绝时有页内对话框。
5. **消息反馈**（覆盖 messageFeedback remote + 版本冲突 reconcile）：点 👍/👎、写备注、重复点撤回；在第二个标签页改同一条反馈后回来再改，应出现「feedback changed elsewhere」类文案而非静默覆盖。

7. **断线恢复**（覆盖 alpha2 connection 恢复重构）：挂起 Host 进程数秒再恢复 → 页面出现连接恢复指示、聚焦视图在重连后仍能渲染历史且滚动位置保留（`focusScrollPositions` 台账）；期间产生的反馈点击应经 `resync()` 重新同步版本。
8. **回归基线**：`yarn typecheck` / `yarn test` 全绿（测试经 alias 直接跑在 alpha2 源上，是最强的兼容性证明）。

## 待人工确认

- **类型层残余差异**：本轮以静态核对（两版 contract 目录零差异 + 全部导入符号逐一验证）判定兼容，未实际跑过对 alpha2 源的 `yarn typecheck`/`yarn test`；若 alpha2 在某类型上做了结构性收窄（如 `RemoteFailure` 已从开放 string code 收为 code 联合——本插件用法兼容，但同类写法未必），第 3 步的 typecheck 是最终裁决。
- **`vitest.config.ts` 的 `server.fs.allow` 仍列原作者 macOS 路径**（`/Users/dingyi/...`）：本机 junction 指向 `C:\Users\Administrator\.dsh\source\current`，vite 对 workspace 外文件的放行依赖该列表；当前测试可跑则无需动，若升级后测试报 fs deny，把 Windows 路径补进 allow 列表。
- **junction vs `yarn install`**：本插件的类型/测试面完全依赖手工 junction（package.json 里反而是 npm rc.2 版本声明）。升级 dsh 源、或任何一次意外的 `yarn install`，都会让两者漂移；长期看建议改为正式的 peerDependencies + `link:` 工作流（见迁移步骤第 6 步）。
- **tests 的 `dsh-api-session-controller` 幽灵依赖**：直接 import 但未声明（靠 junction/hoist 解析）；补 peer/devDependencies 时一并加入。
